How capabilities are classified

Four categories, applied the same way to every claim on this site.

Shared

Available in both editions: local model execution through llama.cpp, quantization of GGUF weights, local providers, plan and approval, verification, and workspace confinement.

Core-exclusive

Free-edition surface only.

  • The free, standalone build — GisCode Core 0.1.0-alpha.1, Apache-2.0 source, published as an unsigned executable.
  • A release cadence of its own: Core ships on its own schedule, independent of the Pro tree.
  • The AdSpace panel. Core has one advertising surface, kept out of Chat, Projects and model selection; it currently serves no advertisement because no provider supports Windows desktop.

Pro-exclusive

Present in the Pro tree. Pro is not distributed, so none of this is offered for download today.

  • Terminal, alongside the shared chat and project workflow.
  • Conversation history and status as their own tabs, where Core keeps history inside Chat and state in the status bar.
  • Developer & Release tooling, Device Preview, Generate Video and GisLogo as first-class workspaces.
  • An iOS build path driven through xtool, which needs macOS, Xcode and xtool to be present.
  • Hosted-writer and self-improvement settings, and custom logo support.

04

The local-first architecture

What actually runs on the machine, and where the boundary sits.

  • One inference path. GisCode starts llama.cpp through a llama-server binary it resolves itself, loads the GGUF you chose, and reports the device it actually used — GPU, CPU, or a split — in Model Manager.
  • Quantization is a file choice, not a hidden setting. Weights from Q8_0 down through Q4_K_M to Q3 and Q2 are all loadable; the documentation states the memory arithmetic (weights, plus KV cache, plus headroom) instead of promising that a model will fit.
  • Providers are optional. Ollama, LM Studio, or any local endpoint that serves /v1/models. Endpoints are loopback by default and a remote one is enabled per provider, deliberately.
  • Two boundaries that do not move. Chat is read-only: it may read a bounded view of the project and cannot create, edit, run or delete anything. Changes are made in Projects, where a diff is reviewed and approved.
  • Verified, not asserted. A write keeps a pre-edit snapshot outside the project tree and is confirmed by reading the bytes back; the task reports the outcome rather than the intention.
  • Nothing leaves the machine by default. No account is required to run a local model, and a connection test sends one word, not project files. The optional hosted and remote routes are off until a person turns them on.

Distributed computing is part of the direction, not the current build: one machine, one model at a time is what ships today.

06

Moving from Core to Pro

Why the free edition is not a trial, and what an upgrade actually means.

  • Core is not limited by time or by a licence check. It is a complete free product for the work its capability contract covers, with no activation or entitlement mechanism in the build.
  • Pro is a separate install, not an unlock. It is built from a private tree; installing Pro does not modify Core, and Core keeps working exactly as it did.
  • Your setup carries over. Both editions are built from one code base and read the same GGUF models and project folders on disk, so moving up is an install rather than a migration.
  • What you gain is the rest of the workflow: terminal, device preview, release tooling and the iOS build path, under one set of approval and verification rules.
  • There is no price and no purchase path today. Pro is not qualified for distribution, so this site does not sell it, quote it or invite payment for it.

Where GisCode actually is
